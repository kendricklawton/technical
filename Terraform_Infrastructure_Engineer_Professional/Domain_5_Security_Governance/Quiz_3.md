## Answer Key & Explanations

1. **B** — Terraform state files store sensitive values in unencrypted JSON by design; platform security relies on backend encryption (SSE-KMS), strict IAM least-privilege, and ephemeral credentials.
2. **B** — In Sentinel, `advisory` warns only, `soft-mandatory` blocks unless overridden by permitted roles, and `hard-mandatory` strictly blocks without override.
3. **A** — `conftest` is the standard OPA utility used in CI to test structured JSON configuration files against Rego policies.
4. **B** — The `vault` provider requests dynamic, time-bound leases directly from HashiCorp Vault secret engines during execution.
5. **B** — Ephemeral values (Terraform v1.10+) allow passing sensitive secrets directly to providers without persisting them in state.
6. **B** — Policy-as-Code gates must sit between plan generation and apply to reject insecure configurations before infrastructure is modified.
7. **A** — `tfplan/v2` evaluates the diff of proposed resource updates; `tfstate/v2` evaluates prior state.
8. **A** — Data sources are re-evaluated during `terraform plan` refresh cycles, ensuring updated secret values are fetched from Vault.
9. **B** — `terraform providers lock` with explicit `-platform` flags downloads and records hashes for all designated operating systems.
10. **B** — Inline skip annotations allow auditable, granular rule suppression with documented justification.
