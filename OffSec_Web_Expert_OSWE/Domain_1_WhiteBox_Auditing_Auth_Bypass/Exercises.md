# Domain 1 — Hands-On Lab Exercises

> **Lab safety & authorisation.** Every exercise targets a deliberately-vulnerable app you deploy yourself (Docker on localhost) or an official practice target you are licensed for. Good sources: **OWASP Juice Shop**, **WebGoat**, **DVWA**, **bWAPP**, **VAmPI**, or small vulnerable apps you write to study a single pattern. Do not test applications you do not own or operate. Treat every exercise as a *code-reading* drill first, exploitation second.

---

## Exercise 1.1 — Map an Unfamiliar Codebase

**Objective:** build a route/auth map before touching a payload.

**Setup:** any medium app with source (a Juice Shop clone, or a Spring/Express sample app).

**Tasks:**
1. Enumerate all routes/controllers and note which require authentication.
2. Identify the authorisation model (how is "admin" decided?).
3. List every dangerous sink (query build, deserialise, render, file write, exec) with file:line.
4. Produce a one-page diagram: sources → middleware → sinks.

**Success criteria:** a written map that lets you answer "which routes skip auth?" and "where could RCE live?" without re-reading the code.

## Exercise 1.2 — Decompile & Debug

**Objective:** recover source from a compiled artifact and prove a path with a breakpoint.

**Setup:** a sample Java `.jar`/`.war` (or a .NET `.dll`).

**Tasks:**
1. Decompile with CFR/Procyon (Java) or ILSpy/dnSpy (.NET).
2. Start the app with a debugger (JDWP for Java, dnSpy for .NET) and attach.
3. Set a breakpoint on an auth check; send a request; inspect the exact values compared.

**Success criteria:** recovered readable source plus a screenshot of the breakpoint showing the compared values.

---

## Exercise 1.3 — PHP Magic-Hash Bypass

**Objective:** exploit a loose hash comparison.

**Setup:** a tiny PHP login that does `if (md5($_POST['p']) == $stored)` with a `0e`-type stored hash.

**Tasks:**
1. Identify the loose `==` in source.
2. Supply a known magic-hash input so both sides are `0e...`.
3. Confirm the bypass, then patch to `===`/`hash_equals` and confirm it is fixed.

**Success criteria:** authenticated without the real password, plus a before/after showing the fix defeats it.

---

## Exercise 1.4 — `strcmp()` / Array Juggling

**Objective:** bypass a `strcmp()`-based check with a type trick.

**Setup:** a PHP endpoint using `strcmp($_POST['token'], $secret) == 0`.

**Tasks:**
1. Spot the loose compare.
2. Send `token[]=x` so `strcmp` receives an array and the check passes.
3. Note the correct fix (strict compare + type validation).

**Success criteria:** the check bypassed via array injection, with the mechanism explained.

---

## Exercise 1.5 — Node.js Operator Injection

**Objective:** bypass auth by controlling JSON types.

**Setup:** an Express + Mongo (or similar) login using `req.body` directly in the query.

**Tasks:**
1. Identify where `req.body` reaches the query unchecked.
2. Send `{"user":"admin","pass":{"$ne":null}}` to log in as admin.
3. Patch with schema validation / `String()` coercion and confirm the fix.

**Success criteria:** admin access via type injection, with the type-trust root cause documented.

---

## Exercise 1.6 — Predictable Reset Token

**Objective:** predict a password-reset token generated by a weak PRNG.

**Setup:** an app generating reset tokens from `mt_rand()`/`java.util.Random`/`random.seed(time)`.

**Tasks:**
1. Find the token-generation code and confirm the non-CSPRNG source.
2. Recover/derive the seed (time-based or leaked) and reproduce the token sequence.
3. Reset a victim account's password using a predicted token.

**Success criteria:** a victim account taken over via a predicted token, plus the CSPRNG remediation.

---

## Exercise 1.7 — JWT Attacks

**Objective:** forge tokens three ways.

**Setup:** a JWT-protected API (deploy a sample with configurable verification).

**Tasks:**
1. `alg:none` — forge an admin token against a server that accepts unsigned tokens.
2. RS256→HS256 confusion — sign with the public key as the HMAC secret against a naive verifier.
3. `kid` injection — manipulate `kid` to control the verification key (SQLi/path traversal).

**Success criteria:** at least two forged-token bypasses working, each with the server-side flaw identified.

---

## Exercise 1.8 — Padding Oracle

**Objective:** decrypt/forge a CBC token via a padding oracle.

**Setup:** an app that decrypts a CBC cookie and reveals padding-validity differences.

**Tasks:**
1. Confirm the oracle (different response on valid vs invalid padding).
2. Use a padding-oracle tool or your own script to decrypt a token.
3. Forge a modified token (e.g. elevate a role field) and authenticate.

**Success criteria:** a decrypted and a forged token, with authenticated-encryption named as the fix.

---

## Exercise 1.9 — Host Header Reset Poisoning

**Objective:** poison a reset link via the Host header.

**Setup:** an app building reset URLs from `Host`.

**Tasks:**
1. Find the URL-building code using the request host.
2. Request a victim reset with `Host: attacker.test` and capture the token at your listener.
3. Patch to a config-fixed canonical host and confirm the poison fails.

**Success criteria:** a captured reset token via Host poisoning, plus the verified fix.

---

## Exercise 1.10 — Automate the Bypass

**Objective:** turn a Domain-1 bypass into clean Python.

**Setup:** any bypass from 1.3–1.9.

**Tasks:**
1. Write a script with `argparse` (target URL) and `requests.Session()`.
2. Perform the bypass end-to-end, printing clear status, and land in an authenticated session.
3. Make it deterministic (handle retries/timing) and idempotent.

**Success criteria:** `python3 exploit.py http://target` reaches the privileged context unattended — the OSWE deliverable shape.

## Consolidation Challenge — Blind Auth-Bypass Review

Take a vulnerable app you have *not* studied, give yourself 60 minutes to find the auth bypass **by reading source only** (no fuzzing), then exploit it and script it. Record how your route/sink map led you to the flaw. This mirrors the opening hour of the OSWE exam.
