### Question 15 (Domain 1: SRE Principles)
What is the consequence of setting an SLO target to $100\%$ availability?
- A. It guarantees the highest quality user experience at minimal cost.
- B. Google Cloud provides a full refund if missed.
- C. It is an antipattern that creates an impossible engineering standard, reduces innovation velocity to zero (any deployment risks breaking $100\%$), and wastes capital because users cannot distinguish between 99.99% and 100% due to client-side ISP reliability limits.
- D. It is required for all banking applications.

---

## Answer Key & Rationales

1. **A** — VPC Service Controls establish security perimeters around Google Cloud managed services, mitigating unauthorized data exfiltration risks.
2. **A** — Policy-as-code admission controllers (Kyverno, Gatekeeper) validate Kubernetes manifests against organizational schemas and limits before admission.
3. **D** — Mutating production systems manually causes configuration drift, breaks reproducibility, and violates immutable infrastructure principles.
4. **B** — Rolling SLO windows continuously drop old historical data as time progresses; past outages roll out after 30 days, restoring the budget.
5. **B** — Cloud Error Reporting parses stack traces and aggregates identical failure signatures into actionable issue groups.
6. **A** — Immutability requires referencing container images by their cryptographic SHA-256 digest (`@sha256:...`) rather than mutable tags.
7. **B** — Privileged Access Manager provides audited, time-delimited, just-in-time privilege escalation without permanent broad role assignments.
8. **A** — Developing automated self-healing software replaces repetitive manual interventions with lasting engineering solutions, directly reducing toil.
9. **D** — Admin Activity Audit Logs record all configuration changes, resource mutations, and administrative calls across Google Cloud projects.
10. **D** — Multi-window alerting pairs a long window with a short window, preventing paging when transient error spikes subside before an engineer responds.
11. **C** — Cloud Build generates non-falsifiable SLSA provenance metadata in Container Analysis, proving exact build source, dependencies, and environment.
12. **C** — Cloud Build supports webhook triggers authenticated with secret tokens and routed over secure VPN/Interconnect connections.
13. **B** — The Incident Commander oversees the strategic response, assigns roles, and maintains situational control rather than writing code.
14. **D** — The Google Cloud Ops Agent and Cloud Logging expect the top-level JSON key `"severity"` to parse and display log severity levels.
15. **C** — Aiming for 100% availability paralyzes delivery velocity and yields diminishing returns because end-user internet connections are inherently imperfect.
